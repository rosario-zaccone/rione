# Notification Service Software Requirements Specification
**Version:** v0.1.0  
**Last Updated:** 2026-06-17

## 1. Scope

The Notification Service manages notification creation, read state, and delivery attempts for relevant platform activity.

## 2. Definitions

- **Notification:** A message generated by the platform for relevant user activity.
- **Unread notification:** A notification that has not been viewed by the recipient.
- **Read notification:** A notification that has been viewed or marked as read by the recipient.
- **Delivery failure:** A failed notification delivery attempt that must not roll back the originating user action.

## 3. Functional Requirements

### NOT-FR-001 - Receive Notifications

The service shall notify registered users about relevant platform activity.

**Acceptance Criteria**
- Users receive notifications for neighbour requests, post interactions, and moderation events.
- The service does not send notifications for interactions hidden by blocking or visibility rules.
- Users can view unread and read notification states.
- Notification delivery failures do not roll back the original user action.

## 4. Business Rules

- **NOT-BR-001:** Notifications are generated for relevant user actions.
- **NOT-BR-002:** Notification delivery must not block or roll back the original action.
- **NOT-BR-003:** Notifications must not be generated for interactions hidden by blocking or visibility rules.

## 5. Non-Functional Requirements

- **NOT-NFR-001:** Notification delivery can be asynchronous.
- **NOT-NFR-002:** Delivery failures must be observable without breaking the originating workflow.
- **NOT-NFR-003:** Notification state changes must be idempotent where possible.
